# PC API 反代服务与内网穿透联动方案

日期：2026-10-12。范围：方案设计；尚未修改运行功能或配置真实服务器。

## 目标与已有能力

在 Codex 管理的 API 反代服务中加入“启用内网穿透”，默认关闭。开启并配置后，外部客户端可以通过公网 HTTPS Base URL 调用本机 API。内网穿透页面统一查看连接、专用规则和状态。

现有代码证据：

- `src-tauri/src/commands/frp.rs`：已有 frps 地址、连接端口、加密 token、本机 frpc 安装、规则校验、状态查询、日志、启停与应用配置。已有 https2http 插件字段和配置渲染。
- 当前 FRP 进程以 server_id 管理；apply_one 会重启对应进程，不能直接把 API 联动加入共享实例后随意重启。
- `src-tauri/src/commands/codex_gateway.rs`：已有手动/自动启动、停止和保存端口后更换监听的流程。
- `src-tauri/src/core/codex/gateway.rs`：支持回环地址或局域网监听，以及 API 服务密钥鉴权。穿透可以连接 127.0.0.1，不要求开启局域网访问。
- `src/platform/clients/frp.ts`：原生 FRP 客户端契约可复用；浏览器预览不具备本机穿透能力。

## 推荐结构

公网调用方 → HTTPS 公网域名 → frps → 本机专用 frpc 的 https2http 插件 → 127.0.0.1:实际网关端口 → API 服务账号池。

复用 FRP 模块的二进制、连接记录、配置校验和状态/日志工具；由 Rust 增加网关联动协调器。新建 API 专用托管实例，引用已有 frps 连接，运行配置独立，避免复制数据库中的明文凭据。内网穿透页面显示“Codex API 托管”标记，并跳转回 API 服务配置。

实例标识必须从单一 server_id 扩展为稳定的运行配置标识（例如 profile_id 或显式实例键）。数据库记录连接引用、所属服务、规则名称和生命周期策略；不允许不同实例共享本机管理端口或配置文件路径。

API 页面负责开启、设置公网访问和展示地址；FRP 页面统一监控、排错与修改通用连接信息。托管规则的本机目标和端口由网关维护，不能在两处分别编辑。

## 界面与配置

在“访问与共享”区域增加“启用内网穿透”开关，默认关闭。打开后展开：

| 字段 | 行为 |
| --- | --- |
| frps 连接 | 选择已有连接，或新建连接并保存到内网穿透模块 |
| frps 地址、连接端口 | 域名/IP 与控制连接端口；新建时填写，已有连接沿用 |
| frps token | 加密保存；空值沿用已有值；不能与 API 服务密钥混用 |
| 公网模式 | 推荐 HTTPS 域名；TCP 端口作为高级模式 |
| HTTPS 域名、公网端口 | 域名指向 frps；默认公网端口 443，允许已有服务器自定义 |
| TLS 证书 | 首期选择现有证书/私钥文件，复用 FRP 路径校验；后续接 HTTPS 证书库 |
| TCP 远端端口 | 仅 TCP 模式需要；校验有效范围和本地规则冲突，远端冲突由 frps 注册结果确认 |
| 本机目标 | 固定为 127.0.0.1 和网关实际监听端口，只读 |

显示“公网 Base URL”、连接状态、配置测试、打开内网穿透管理、复制地址。复制分享配置只引用原有 API 分享流程，密钥必须通过明确的分享动作处理，不能写进 URL、日志或普通配置导出。

区分“开关开启/待配置”和“穿透已连接”，保存配置成功不代表公网可用。未安装 frpc 时显示现有安装入口。开关关闭时不创建规则、不启动进程、不探测公网。

## 公网模式选择

| 方案 | 条件及成本 | 复杂度与适用范围 |
| --- | --- | --- |
| HTTPS + https2http（推荐） | 已有 frps 提供 vhostHTTPSPort；域名与有效证书；流量使用现有服务器 | 复用已有插件，HTTPS 在本机 frpc 终止，公网请求保持 API 密钥鉴权 |
| TCP + 服务端 HTTPS 反代 | frps 开放远端端口；服务端 Nginx/Caddy 等负责 HTTPS | 适合已有服务器入口；应用只展示用户配置并验证的 HTTPS 地址，不自动声称 TCP 具有公网 TLS |
| TCP 直接 HTTP | 无域名也能配置，但公网调用链路未加密 | 仅显式选择的测试模式；FRP 控制连接 TLS 不等于调用方到 frps 的 HTTPS |

frps 控制端口与 HTTPS 公网端口是不同用途。开启桌面开关不会自动在远端安装 frps、放行防火墙或改 DNS；提供配置说明，由用户完成已有服务器的前置设置。不要要求填写 frps Web 管理密码作为穿透认证。

## 生命周期与失败处理

1. 保存配置：校验地址、端口、唯一规则名、证书与域名匹配，写入本地配置；服务未启动时只进入“等待 API 服务”。
2. 启动 API：先监听本机并确认鉴权配置，再以实际端口生成专用 frpc 配置、执行 verify、启动并检查指定代理注册状态。
3. 穿透失败：保持本机 API 可用；显示“本机可用、公网连接失败”，分类提示认证、连接、端口、域名或证书问题，提供重试。
4. 停止 API：先停止专用穿透实例，再停止网关；不停止用户其他 FRP 实例。
5. 修改 API 端口：先暂停专用穿透，使用网关现有替换监听逻辑；成功后重生成配置并重新验证。失败时根据实际监听恢复旧目标，不能转发到旧端口上的其他进程。
6. 关闭穿透：立即停止专用实例并禁用关联规则，保留 frps 连接供其他服务使用。
7. 自动启动：仅当 API 自动启动与穿透开关均开启且配置完整时，按相同顺序联动；失败不阻塞桌面打开。
8. 桌面退出：停止专用实例；最小化到托盘时沿用应用生命周期。电脑关机或休眠时不能继续提供公网 API。
9. frps 重连：复用 frpc 重连能力，界面通过指定代理状态反馈；配置错误不无限重启，运行任务互斥且可取消。

不能用整个 frpc 的 connected=true 判断 API 规则成功，因为现有实现只要任一代理 running 即视为已连接。必须核对托管规则名称与状态。

## 数据、安全与可用性

新增 `codex_gateway_tunnel` 配置：enabled 默认 false、server_id 引用、托管实例/规则标识、模式、公网域名/端口、证书来源及引用。frps token 继续使用原有连接的加密存储，API 服务密钥继续使用原有网关存储。

公网地址显示“已配置”“代理已注册”“外部访问已验证”三个层次。从本机访问公网失败可能是回流限制，不能只凭本机探测宣告外网不可用。基础测试不发起计费推理；首期验证 TLS 和无凭据请求被拒绝，进一步完整调用由用户显式测试。

对控制通道补充受信 CA/服务器名称校验配置与验证，不把当前 transport.tls.enable=true 等同于远端身份已验证。TLS 文件应限制本机用户读取权限。后续从证书库生成受限临时 PEM 时需要明确生命周期和续签后的重载。

连接状态之外，公网入口至少校验 API 密钥必需、请求体大小、并发与基础限流策略。优先复用现有约束，查明缺项后实现，不能仅以 frpc 进程存在判定安全或可用。

# 数据同步范围审查与统一方案

日期：2026-10-29。状态：已获用户确认并实施，验证结果见文末。以下问题清单保留实施前审查结论，包含此前尚未提交的多渠道和恢复交互改动；未读取用户数据库、密钥或实际备份内容，未对用户数据执行恢复。

## 结论

目前“业务配置可迁移、运行状态留本机”的方向合理。SQL、扫码迁移、本地与云端备份已引用 `src-tauri/src/core/data_transfer.rs` 的同一份 26 表白名单，适合继续收敛，不需要重写同步系统。

但“同一表名单”尚未等于“相同范围和恢复语义”。需优先解决关联范围隐式扩大、接口默认替换、回收站差异和备份遗漏。云同步当前实际是版本化快照上传与手动恢复，不是双向实时同步；不应暗示会自动合并各设备的修改和删除。

## 已核实的问题

| 优先级 | 事实与证据 | 影响 / 处理建议 |
| --- | --- | --- |
| P0 | `database_sql.rs::selected` 自动加入父表；`restore_portable_selection` 将扩大后的表集合交给同一个 replace 模式。`DataTransferScope` 只泛称关联父记录一并处理，未展示最终范围。 | 只选证书/SSH等子模块，也可能使云账号进入替换范围。未选子表有外键时有阻止级联保护，但不能代替明确授权。自动补齐父记录只允许追加/匹配，不允许隐式清空父模块。 |
| P0 | `DataImportReview` 默认 merge，但 `database_migration.rs::confirm_database_import` 缺少 mode 时仍 `unwrap_or("replace")`。 | 当前界面显式传 mode，不等于每个调用方都安全。统一缺省 merge；replace 必须显式提交已预览的影响范围与确认。 |
| P1 | `App.tsx` 挂载 `DataImportReview` 的回调仅传 tables、mode，丢弃 forceRestore；手机的 `UnifiedMigrationPanel` 会传该字段。 | 桌面勾选“创建可在备份管理恢复的备份”未生效。原生通常仍保存 before-import 快照，不能说完全没有保护；应统一为可见、可管理的恢复前备份。 |
| P1 | `.chdb` 的 `sanitize_snapshot_with_key` 保留白名单中的软删除行；SQL/扫码的 `portable_copy` 默认剔除回收站。 | 名称相近但默认范围不同。明确区分快照备份包含回收站与迁移默认不包含，恢复独立选择是否导入回收站。 |
| P1 | 云盘连接保存在偏好 `cloud.drive.connections`，不满足 `portable_preference`；其独立 JSON 导入导出不能补齐统一备份。 | 用户可能误以为备份了全部连接。增加“云盘连接配置”独立模块，排除盘符、挂载状态和缓存，不能简单把加密偏好加入白名单。 |
| P1 | 实际收藏、资产备注/显示名/排序等键是 `cloudhub-tools-*`；`portable_preference` 允许 `theme`、`ui.*` 等，与实际键明显不完全对应。 | “可迁移偏好”不能保证包含用户维护的资产元数据；含账户本地数字 ID 的资源引用迁移后还需重映射。 |
| P1 | `database_sql.rs::identity` 对备忘录使用 created_at+title，对账号使用厂商+AccessKey ID，部分表回退主键；导入还会重新生成 sync_id。 | 这是迁移去重规则，不能当双向同步身份。改标题、换凭据、同标题同时间可能产生重复或误匹配。逐模块定义稳定迁移标识和兼容回退规则；禁止直接信任导入的设备授权身份。 |
| P1 | 备份预览的 conflicts 主要检查账号、主机、面板，缺少所选全部模块的新增/覆盖/删除统计。 | 确认文案不能准确说明覆盖影响。统一执行前试算计划，按模块给出 added/updated/skipped/deleted。 |
| P2 | 云渠道上传和本地备份都固定完整业务白名单；SQL和扫码可选表。扫码 v5 接收端固定 merge；浏览器恢复要求明确传范围和模式。 | 各入口交互/能力不同，应共享策略和说明，不强迫平台提供不支持能力。扫码首期保持追加即可，明确告知。 |
| P2 | 普通 `.chdb` 携带恢复密钥，可选密码才整体加密；旧备份无策略标记时不恢复OTP。 | 不应把字段密文称为只有本人可解密；历史兼容与OTP跳过需在预览中解释。云渠道建议启用密码保护并持久展示保护状态。 |

## 推荐统一范围

以业务模块对用户展示，表名留在内部。每个模块定义包含项、依赖、敏感级别、迁移身份、字段清理、跨端能力与回收站规则。

| 模块 | 建议范围 | 默认规则 |
| --- | --- | --- |
| 云账号 | 厂商、分组、备注、启用状态、账号凭据 | 可备份迁移；资源列表/详情缓存不包含 |
| 主机连接 | 托管主机、SSH/RDP、认证材料、必要账号引用 | 可迁移；源主机信任指纹需独立信任策略，不直接当目标设备已确认 |
| 面板与证书 | 面板连接、证书/私钥、历史版本、来源/部署关联 | 同一模块内可细选；外部账号/面板依赖明确列出；不触发部署或续期 |
| 流水线 | 连接、组织配置与凭据 | 不含流水线查询缓存、构建记录和日志 |
| FRP | 服务端、客户端与规则配置 | 不含进程、下载二进制、运行状态；恢复后不自动启动 |
| AI与供应商 | AI配置、Claude/Codex供应商、密钥、聚合及成员 | 不含Codex登录账号、OAuth、网关绑定和本机配置文件接管 |
| 备忘录 | 分组、正文、提醒设置 | 提醒调度由目标设备重建；不重复搬运已发送记录 |
| 指纹浏览器 | 环境配置、代理认证 | 不含浏览器用户目录、Cookie、登录态、内核与下载文件 |
| 验证器 | 名称、种子、类型及HOTP计数 | 高敏模块，明确可选；相同种子去重，HOTP不回退；旧包不支持时保留本机 |
| 云盘连接（补齐） | 厂商、端点、桶、前缀、认证 | 不含源设备盘符、自动挂载、缓存目录和文件缓存；恢复后先配置本机挂载 |
| 资产自定义信息（补齐） | 收藏、备注、自定义名称、业务排序 | 引用稳定资源身份；不依赖源设备账户数字ID；资源缓存缺失时保留待关联元数据 |
| 外观偏好 | 实际使用的主题、语言等精确白名单 | 作为可选模块；移动悬浮按钮位置、窗口尺寸、缩放、路径、端口等留本机 |

默认排除：日志/审计、资源与性能缓存、设备身份/信任授权、同步队列与删除传播状态、云同步渠道凭据、下载文件与运行包、Codex登录态、本机配置文件及自动执行状态。

云同步渠道自身仍留本机，避免恢复后自动覆盖上传目的地或覆盖云端版本。若需要渠道迁移，提供独立显式导出，恢复后关闭自动上传并重新确认连接。

## 各入口采用同一策略，保留用途差异

| 入口 | 内容默认范围 | 回收站 | 导入/恢复 |
| --- | --- | --- | --- |
| 本地业务备份 | 完整业务模块；可选自定义范围 | 备份包含，以保留恢复能力；清楚标示 | 默认追加；回收站恢复默认不勾选 |
| 云渠道 | 每渠道保存范围，默认完整业务模块 | 与本地业务备份一致 | 下载选版本，再选模块/方式，不自动应用 |
| SQL交换 | 同一目录中可选模块；明确明文凭据风险 | 默认不包含，可选 | 默认追加；支持覆盖重复；完整替换不作为SQL快捷操作 |
| 手机扫码迁移 | 同一目录中可选模块和必要记录依赖 | 默认不包含，可选 | 首期明确只追加；后续如开放覆盖必须接入统一影响预览 |
| 手机备份/云下载 | 能保存相同业务数据 | 同一规则 | 使用相同预览与恢复引擎；桌面专属数据可保存，标明当前平台不能执行 |
| 账号/供应商/证书/云盘独立导入导出 | 仅本模块范围 | 按模块契约 | 保留兼容格式；遵循统一身份、冲突和加密规则，不冒充全量备份 |
| 浏览器调试 | 仅本机API实际支持的入口 | 跟随共享引擎 | 不模拟原生执行能力；Rust桥接不可用就明确不可用 |

## 统一恢复语义

1. 追加（默认）：只新增记录，重复保留本地；HOTP计数单调递增是安全例外，预览说明。
2. 覆盖重复：只更新匹配项，保留本地独有数据；显示预计覆盖数并确认。
3. 替换所选模块：使明确选择的业务模块与备份一致，删除其中本地独有记录；删除范围必须逐模块列出。不要承诺物理执行顺序是“先清空”，现实现为先合并后清除未保留行。

自动依赖只补齐被引用的必要父记录；不能因为恢复一条证书就整表导出所有云账号，也不能把自动依赖加入删除范围。用户主动选择父模块替换时才可删除，并再次校验未选模块的引用。

预览应返回：requestedModules、dependencyModules、effectiveModules、按模块的新增/更新/跳过/删除数量、敏感项摘要、不可用能力和源策略版本。执行确认绑定预览计划和目标数据版本；目标发生变化则重新预览，避免统计与实际不一致。

执行前生成可在备份管理中找到的本机恢复备份，失败即终止；在事务中应用，失败回滚。执行后给出按模块结果，不自动启动FRP/浏览器/网关，不自动续期/部署证书，不接管AI客户端文件。

恢复实际提交后暂停自动上传，防止恢复结果立即变成新的自动上传；下载预览取消与恢复成功分别显示状态，避免用户不知道为何自动上传暂停。

## 方案比较

| 方案 | 安全与数据归属 | 工作量/复杂度 | 可逆性与验证 |
| --- | --- | --- | --- |
| 仅修界面文案 | 无法消除底层范围/依赖差异 | 低 | 易回退，但无法证明恢复范围正确 |
| 扩展现有共享策略与恢复计划（推荐） | 沿用本地SQLite与本机加密；统一明确授权范围 | 中；主要是Rust、契约和共享UI，无新服务 | 按策略版本兼容旧包；可用跨入口夹具验证 |
| 重建双向实时同步 | 还需版本冲突、删除传播、身份授权与跨端密钥设计 | 高；与当前快照需求不同 | 回退复杂，不能用本轮范围对齐替代设计 |

## 实施顺序与验收

以下为已确认的实施顺序；本轮在现有共享策略及导入引擎上完成对齐。

1. **收紧恢复边界**：Rust `database_migration.rs`、`database_sql.rs` 与React `DataImportReview`/`App.tsx`。默认merge，透传forceRestore，区分用户范围和依赖范围，replace只能删除明确选中模块。验收：省略mode不删除；只替换子模块不会删除未选父模块；依赖冲突整体回滚。
2. **建立共享模块目录**：扩展 `core/data_transfer.rs` 的版本化策略并提供Tauri目录命令；DTO由同一契约提供给React和Node。依赖步骤1。验收：每个持久化表/偏好明确归类，新增结构未分类时检查失败；不再用 `ui.*` 等宽泛前缀自动允许未知配置。
3. **补齐缺失业务数据**：增加云盘连接和资产自定义信息适配器，精确外观偏好；加密偏好须解密后按包密钥封装，不能原样跨设备复制。依赖步骤2。验收：不同设备密钥可恢复、引用可重映射，云盘不自动挂载；云同步渠道仍排除。
4. **统一快照与迁移范围**：本地/cloud快照使用相同投影与清理函数；统一manifest写入真实有效模块、policyVersion、回收站策略、凭据保护模式与平台信息；旧包读取保留兼容。依赖步骤2、3。验收：同一源数据在不同入口的有效业务内容一致，差异仅为用户选项及格式。
5. **统一预览与冲突处理**：所有恢复入口使用恢复计划；模块分组UI、必要依赖提示、删除数量、覆盖确认和结果摘要共用，手机扫码先保持只追加。依赖步骤1、4。验收：桌面、手机、本地API同一选择返回同一结果，窄屏不溢出，取消不写业务数据。
6. **完整回归与兼容验收**：运行构建、Rust检查、Node语法/参数测试与平台契约检查；以不同本地ID/密钥、相同自然键、标题修改、回收站父子记录、旧包/未来版本、OTP、空模块、恢复中失败及自动上传暂停为夹具。验收：新增/覆盖/跳过/删除统计与实际一致；无敏感日志；未选模块和本机身份不变；跨平台保存与执行能力不混淆。

## 审查边界

最初审查为静态调用链证据，不是已复现的用户数据损坏。实施验证使用隔离夹具和页面模拟，未对用户数据执行真实恢复、云端上传或设备迁移。独立模块的第三方导入格式保留原有兼容入口，本轮未逐一改写这些格式；不承诺未经逐项验证的第三方格式已经采用统一恢复计划。

## 实施结果

- 策略升级为 v2，统一 28 项表/投影目录，补齐云盘连接与资产自定义信息，偏好改为精确白名单；本机身份、渠道、缓存和运行状态不迁移。
- 本地备份、云渠道范围、SQL、扫码及手机恢复复用共享范围及字段清理。云盘连接跨密钥重加密，资产引用重映射；恢复不自动挂载或启动进程。
- 恢复默认追加；覆盖重复和替换所选模块须明确确认。必要依赖仅追加，替换会保护未选模块的引用，冲突回滚。
- 本地/云端备份和 SQL 恢复先计算逐模块影响，确认绑定范围、方式、回收站和本机数据版本；恢复成功返回逐模块统计。扫码保持只追加。
- 恢复和 v5 扫码确认前创建可管理的本机恢复备份，失败即终止；自动上传仅在成功提交后暂停，取消下载预览不再暂停。
- 桌面和手机共用分组范围、恢复方式、回收站开关及影响预览；手机仅保存桌面专属配置。

验证通过：`npm run build`、移动目标 Vite 构建、`cargo check`、32 项数据库 Rust 测试、1 项扫码 v5 往返测试、14 项 Node 测试（使用本轮编译的隔离 Rust 桥接程序）、14 项桌面页面测试、2 项手机页面测试，以及平台契约、Rust 命令边界、四个 Node 文件的语法检查。构建仍有包体积、未使用代码和依赖未来兼容性警告，未阻止构建。

尚未执行真实云渠道联网、实体 Android/iOS 安装或扫码相机验收；未发布新版本。当前构建输出已恢复为桌面目标。

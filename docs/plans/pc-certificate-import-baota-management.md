# PC 桌面端证书导入与宝塔证书管理方案

调研日期：2026-10-12。范围：方案设计，不修改证书功能，不调用真实面板、不执行续签或部署。

## 可行性与边界

新增手动导入、宝塔来源两类证书可行，保留现有 CloudHub ACME 申请来源。来源和签发者分别建模：手动导入也可能是 Let's Encrypt，宝塔来源也可能是商用证书。

宝塔站点元数据读取和自定义证书部署有官方接口。面板 ACME 订单支持读取材料和续签；所有站点证书均能取得私钥、所有证书均能续签，这两个结论不能成立。官方说明接口可能随版本变化，实施前需要在目标面板版本进行兼容性验证。

官方依据：
- [API 概览](https://docs.bt.cn/api)
- [站点 SSL 信息](https://docs.bt.cn/api/site/getssl)
- [自定义证书部署](https://docs.bt.cn/api/site/setssl)
- [ACME 查询、下载、续签与部署](https://docs.bt.cn/api/acme/actions/)
- [证书夹查询](https://docs.bt.cn/api/ssl/actions/)

## 一、手动导入

入口：HTTPS 证书 → 添加证书 → 手动导入。支持粘贴证书链和私钥、选择两个文件、拖放或选择 ZIP。第一阶段支持 PEM、CRT、CER、KEY 和包含这些文件的 ZIP；DER CER 识别后可转换，PFX/P12、RAR、7z 后续扩展，不将现有可选 openssl 命令视为用户电脑必备依赖。

Rust 检查证书结构、SAN、有效期、签发者、指纹、RSA/ECC 公钥与私钥匹配、链中证书关系。用户可导入过期证书用于归档，但部署操作单独检查适用性。中间证书缺失给出提示，不仅根据文件名判断。多个证书或密钥时展示候选配对供选择，不静默取第一对。重复证书使用指纹去重，覆盖域名相同的新证书作为新版本保留。

ZIP 建议限制：文件 10 MiB、解压后 20 MiB、100 项，实施时作为可调整产品限制。只读取候选文件，拒绝路径穿越、绝对路径、符号链接、嵌套压缩包和压缩炸弹；优先内存解析，不直接解压到任意目录。导入预览仅返回元数据和临时句柄，确认后加密保存，取消销毁临时材料。粘贴私钥必须短暂通过原生命令传入，使用遮罩输入，提交或取消后清空，不进入持久前端状态、日志或错误。

导入证书不能凭证书和私钥自动续签。没有原申请订单和有效域名验证配置时，提供替换证书；若用户选择交给 CloudHub 管理，则重新配置域名验证并申请新的证书。

## 二、宝塔来源

复用已保存的宝塔连接、加密 API 密钥及签名。选择面板后分页同步站点，在 Rust 内调用 GetSSL，结合证书夹与 ACME 订单建立站点、证书、订单关系。记录 panel_id、site_id、site_name、order_index、ssl_hash、指纹和最近同步时间；不要将 GetSSL 的 oid 直接当作 ACME index，也不要只按域名猜测订单。

默认同步元数据，不批量复制所有私钥。用户选择“导入到本地证书库”时，对已确定关联的 ACME 订单使用 get_order_find/download_cert；Rust 接收材料、验证并加密，仅返回元数据。GetSSL 文档中 key/csr 是存在性布尔值，不能据此声称取得 PEM。自定义和商用证书若目标版本没有可用材料接口，标为远端管理记录，不提供本地导出或 ESA 部署；可由用户另行手动导入材料，不默认调用任意文件读取 API 或 SSH 绕过。

能力探测区分：查看、获取材料、续签、部署、强制 HTTPS。先支持宝塔 Linux 常规网站；Windows、特殊项目和旧版本分别验证，不自动套用相同适配器。读取状态要按接口解码：GetSSL 的 status=false 可以表示未部署 SSL，不应沿用“任意 status=false 均请求失败”的通用规则。现有 panel_api_request 只传签名且统一判断失败，需增加受控业务参数和接口专用响应处理。

## 三、续签与管理

仅对能明确关联 ACME 订单、面板支持 renew_cert 且原验证条件仍可用的证书显示“续签”。HTTP/DNS 验证由面板执行；通配符采用 DNS 验证，默认复用面板已有配置，不把 CloudHub 的云密钥同步给面板。商用、自签名及无订单的导入证书显示“替换”或“重新申请”。

执行流程：检查能力和目标 → 按面板及订单加锁 → 调用 renew_cert(index) → 回读订单和新证书 → 验证指纹、域名及有效期 → 确认目标站点 → 必要时 SetCertToSite → 回读 GetSSL → 更新本地记录。续签成功和部署生效分开记录，不以 HTTP 200 或单个 status=true 作为站点更新完成。网络超时标为结果待确认，先回读再重试，避免重复申请触发 CA 限额；取消客户端等待不等于面板取消执行。

支持远端状态刷新、到期提醒、导入本地、续签、部署本地证书、打开面板。删除本地记录与关闭站点 HTTPS、删除远端订单、CA 吊销分别处理；第一阶段不把后三项混为一个删除按钮。部署前保存可恢复版本与站点关联，失败保留旧版本；能够取得旧材料时提供回滚，不能保证恢复时明确说明。

自动续签优先由宝塔服务器现有调度负责。CloudHub PC 提供查询、提醒及手动触发，关闭应用后不承诺继续执行本地任务。后续启用自动策略前需验证目标面板调度和续签能力，避免与面板已有任务重复触发。

## 四、数据与桌面执行层

现有 certificates 表强制 account_id，并与云账号级联删除，dns_zone 也必填；手动和宝塔证书不应被迫绑定虚假云账号。迁移时使云账号关联可空，增加 source_kind，签发者/provider 独立保留；DNS 申请配置只对 CloudHub ACME 来源要求。来源关联解除不删除本地已导入材料，删除云账号/面板的行为需显式回归验证。

建议新增 certificate_source_links 和 certificate_versions：一个证书可关联多个面板站点，来源关系保存远端标识与能力，版本保存指纹、有效期、加密材料与当前版本。证书没有本地私钥时明确标为仅元数据，禁止导出或部署。复用现有 SQLite 加密、导出和 ESA 原生部署流程，审核当前“按云账号筛选证书”逻辑，允许显式选择本地证书并校验目标域名。

React 复用 CertificatePanel 和既有样式；Rust 承担导入解析、密钥匹配、面板请求、续签任务与部署；前端只接收元数据及进度。浏览器预览只提供既有只读摘要，不新增私钥读取或续签降级服务。PC 使用本地文件，不向额外云服务上传压缩包。面板 HTTPS 校验默认开启，新增证书能力不得自动启用跳过校验；API 白名单和连接认证沿用实际面板配置。

## 五、实施阶段与验收

1. 在选定面板版本进行只读兼容性验证：站点分页、GetSSL、ACME 订单标识和材料接口，记录脱敏响应结构。不能访问真实面板时保留未验证标记。
2. 数据迁移、手动粘贴/文件/ZIP导入及统一列表；验证 RSA/ECC、链、错误配对、重复指纹、ZIP攻击样例和敏感材料清理。
3. 宝塔站点同步、来源关联、能力状态和按需本地导入；验证无证书、无订单、断网、权限不足及版本不支持。
4. 在测试站点验证续签、部署回读、超时恢复、多站点影响和可用回滚；再接入到期提醒与策略展示。

实现验收执行 npm run build、cargo check 和相应单元/界面测试；当前仅完成代码和官方文档调研，没有进行真实面板调用或生产续签。

## 实施结果（2026-10-12）

PC 桌面端入口位于 HTTPS 证书页面：导入证书支持粘贴、文件选择和拖放ZIP；宝塔站点证书页可选择已有 HTTPS 面板连接并获取站点列表，显示名称、域名、备注和面板来源。续签按钮仅在证书身份与原订单明确匹配时可用。材料缺失或面板不支持时显示原因，不伪造成功。

原生续签依次核对站点与原订单、提交续签、读取新有效期和域名、部署及指纹回读。部分完成与完整部署分别显示；不确定结果持久保留重试保护，用户核对面板结果后可解除保护并重新同步。新证书加密保存，旧证书记录保留，可通过部署证书选择已有有效版本。

验收：前端构建、Rust检查、平台契约和命令边界通过。Rust全量229通过，3项既有忽略；10项界面回归通过。原生HTTP模拟面板覆盖完整续签链、部署失败、未更新有效期、遗漏域名及旧证书回读。实际宝塔版本的兼容性和生产续签未验证；没有对真实站点执行写入。PC关闭后的自动续签仍由宝塔自身负责。

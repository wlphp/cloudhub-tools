# CloudHub Tools 可选 AI 辅助集成方案

日期：2026-10-13。状态：实施中；配置、加密文件迁移和基础调用已加入，实际验收进度以任务记录为准。

## 实施顺序补充

优先交付可实际使用的服务配置、服务器/DNS识别、常用命令生成和选中终端输出分析；其余业务入口继续保留在完整范围和任务记录中，分别验证后开放。稳定格式先走本地解析，用户主动触发AI处理杂乱内容，不在应用启动、粘贴或切换页面时自动产生调用。

服务配置与用途选择分离：文本和图像可以选择不同服务，图像能力以实际测试为准。调用记录仅保存功能、耗时、状态和用量等元数据；额度提醒与请求限制不等同于供应商账单上限。每个入口都需要验证未配置、停用、不可达时的手动流程，并验证候选结果不会自动保存或执行。

流式响应先显示接收进度；完整结构化结果通过校验后再展示字段。非流式和流式响应均拒绝工具调用，避免服务在文本旁附带未授权动作。图像能力缓存绑定配置修订号，修改配置后需重新测试。

## 目标与推荐方案

系统设置增加「AI 服务」；通过用户配置的 OpenAI、Claude/Anthropic 或 Gemini 协议，为现有业务提供识别、解释、草稿生成和检索辅助。配置可以是官方服务、兼容网关或用户主动选择的本地服务。

推荐统一的原生 AI 调用模块和按业务定义的辅助任务。模型只产生候选字段、诊断报告、命令草稿或筛选条件；应用负责数据验证，用户决定应用哪些结果。所有原有手动流程、规则解析和确定性校验保留，不配置 AI、关闭 AI、超时或限流时仍能完成原有操作。

可比较路径：

| 路径 | 成本与复杂度 | 数据与可靠性 | 结论 |
| --- | --- | --- | --- |
| 每个页面单独调用模型 | 起步快，但重复维护三种协议、密钥与错误处理 | 脱敏和权限容易不一致 | 不采用 |
| 统一原生调用模块，按业务输出草稿 | 中等投入；调用次数和上下文可控 | 复用加密和本地校验，失败可回退 | 推荐 |
| 全局 Agent 自动操作资源 | 较高成本，工具权限和恢复复杂 | 存在误操作、上下文泄露和执行风险 | 本轮不纳入 |

## 已核对的代码基础

- 系统设置目前在 `src/App.tsx`；偏好客户端为 `src/platform/clients/preferences.ts`，`client_preferences` 会将值作为普通文本存储，不适合存放模型 API Key。
- 本地加密可复用 `src-tauri/src/core/crypto.rs`；持久化与迁移在 `src-tauri/src/core/database.rs`、`src-tauri/src/core/repositories/`。
- 平台调用统一通过 `src/platform/clients/`；新增 `ai.ts`，不让业务页面直接请求供应商。
- DNS 已有本地解析器 `src/features/domains/parseDnsPaste.ts`，继续作为默认解析路径。
- Codex 网关已经有三协议相关实现 `src-tauri/src/core/codex/protocols.rs`。它属于对外网关，不等于应用内模型客户端；只复用可独立验证的格式、错误和网络工具，不直接依赖账号池运行。
- 终端常用命令、录像审计、云效日志、证书、FRP 等有明确业务入口；可插入辅助操作而无需替换管理流程。
- 整库迁移在 `src-tauri/src/commands/database_migration.rs`；选择式迁移在 `src-tauri/src/core/repositories/sync.rs` 及 `src/features/accounts/SyncTransferPanel.tsx`，需要显式扩展 AI 配置类别。

## 系统设置中的配置

支持保存多份服务配置，选择一个默认服务，并可为图像识别选择不同服务；首期界面保持紧凑，不要求用户同时配置三家。

基础字段：启用开关、配置名称、协议、Base URL、API Key、模型名称。OpenAI 协议额外选择 Responses 或 Chat Completions 模式；第三方兼容服务不能假定支持 Responses。模型可以直接填写，服务支持列表接口时提供下拉查询。

高级字段：请求超时、输出 Token 上限、文本/图像能力状态、各业务入口开关。能力显示「未验证/可用/不可用」，按实际测试和接口响应更新，不仅凭模型名称猜测。图像识别只对支持图像输入的配置启用。

提供保存、测试连接、测试文本识别、测试图像能力、设为默认和删除。测试使用固定无敏感样例，并提示测试会产生模型调用。配置列表只返回脱敏信息与 hasKey，不回读明文密钥；编辑时留空保留已保存密钥。

API Key 加密落库，不能放 localStorage 或普通偏好字段。整库加密备份纳入新数据表；跨设备配置迁移增加显式选择项，默认不携带密钥，携带时沿用已有口令加密迁移与冲突预览流程。手机端不复用桌面整库导入方式。

实施决策：AI配置提供独立的口令加密文件迁移，复用现有 SyncEnvelope 加密和原生文件保存路径，避免修改已使用的扫码配置包版本。导入先预览、再确认新增；同名配置自动改名，保留现有配置。导入配置始终停用，用户核对地址并补填缺失密钥后才能启用。二维码迁移可在后续扩展，文件迁移已覆盖桌面与手机的数据携带需求。

费用控制以输入大小、输出上限、并发上限和请求次数限制为主。显示供应商实际返回的 Token 使用量；金额仅在用户维护单价时估算，标记为估算，不承诺应用能精确控制供应商账单。

## 功能机会与实施优先级

| 位置 | AI 辅助功能 | 保留的原有路径 | 阶段 |
| --- | --- | --- | --- |
| 服务器添加/编辑 | 从文字或已遮挡截图提取名称、主机、端口、操作系统、用户名、分组和备注；批量预览、重复项提示 | 手动填写、现有导入 | 首批 |
| 面板添加/编辑 | 从安装说明提取面板地址、名称与服务器关联候选 | 手动填写；密钥仍本地输入 | 首批 |
| DNS 编辑 | 解析杂乱文字/截图、多记录说明；对 SPF/DMARC/CAA 等提供逐条解释。批量结果在本地校验并可逐条勾选，重复项明确提示 | 本地粘贴规则解析、手动编辑、现有校验；AI 候选逐条审核，仍由用户确认保存 | 首批 |
| 资产管理/收藏 | 从购买信息、产品说明、网址说明中整理名称、类型、期限、标签、备注 | 手动编辑与现有导入；已有字段之外只输出备注草稿 | 首批 |
| 终端常用命令 | 描述需求生成命令草稿、解释参数、提示破坏性操作，保存为常用命令 | 手动添加、填入终端后自行执行 | 第二批 |
| 终端输出/录像审计 | 对选中输出解释错误、定位候选原因和下一步检查建议 | 原有终端、录像查询与回放 | 第二批 |
| 云效流水线 | 对所选失败日志归纳原因、区分证据与推测、给出修复建议 | 原有运行详情、日志与重跑入口 | 第二批 |
| 操作日志/API 日志 | 分析用户选择的已脱敏日志片段，按时间和错误分类总结 | 原有筛选、日志详情 | 第二批 |
| HTTPS 证书 | 解释申请失败；按已选申请域名与目标站点给出域名覆盖检查建议，并基于现有状态说明部署检查项，不冒充 DNS/ACME 实测 | 现有 DNS/ACME 校验、申请和部署流程；AI 建议不触发签发或部署 | 第三批 |
| 内网穿透 FRP | 自然语言生成规则草稿、解释端口冲突和配置错误 | 原有表单、配置校验和启动流程 | 第三批 |
| 服务器/面板监控、RDS/Redis | 根据明确选择的 SSH 或面板指标解释异常、提出排查顺序和容量建议；面板只发送状态、负载及资源百分比白名单 | 原有指标及厂商操作，结论不替代实际检测；不发送主机地址、账号或原始接口响应 | 第三批 |
| OSS、域名和云资源 | 解释当前权限/配置；根据选定元数据提出配置草稿和整理建议 | 原有配置界面、上传下载和厂商接口 | 第三批 |
| 跨资源查询 | 把「找某分组里即将到期的资源」转为允许的筛选条件，在本地执行检索 | 普通搜索和筛选；不把全库发给模型 | 第三批 |
| 云账号、验证器、Codex 账号 | 不接入表单字段识别或账户导入 AI；仅在用户主动选择已脱敏日志时解释公开错误说明。验证器种子、云密钥、Codex Token 均不进入 AI 上下文 | 既有加密存储、二维码解析、授权和配额管理；保留敏感凭据完全脱离 AI 的设计 | 限定辅助 |

不为开关、排序、简单数字计算或已经稳定的导入格式增加付费调用。首批先实现文本识别，截图识别作为同阶段后半步，在能力和遮挡流程通过验收后启用。暂不对任意文件、整个 OSS 对象内容或完整终端历史进行自动分析。

## 统一交互

业务页使用「AI 识别」「AI 分析」「生成草稿」等明确按钮，不在粘贴、切换页签或启动应用时自动调用。未配置时可去系统设置，手动流程继续可用。

流程：选择/粘贴内容 → 查看将发送的内容和服务 → 发起识别或分析 → 编辑候选结果 → 应用到表单/复制/填入 → 用户按原有方式保存或执行。

识别结果逐字段显示原文依据、缺失字段与需要确认的歧义；未知值留空，不能编造密码、账号所属关系、价格或到期时间。再次识别不覆盖用户已经修改的字段，应用时显示差异。

长任务支持取消、流式进度、超时和重试。切换页面或关闭弹层取消关联请求，旧响应不能覆盖新请求。错误、拒绝、能力不支持和结果不合法分别反馈，并保留输入与手动编辑状态。

## 技术与安全边界

React 负责呈现与选择上下文；Rust 负责凭据读取、脱敏、协议请求、任务取消、结果校验。拟新增 `src/features/ai/`、`src/platform/clients/ai.ts`、`src-tauri/src/commands/ai.rs`、`src-tauri/src/core/ai/`、AI 配置 repository 和数据库迁移。业务辅助任务采用封闭枚举与字段 schema，不开放任意 prompt 加工具执行接口。

统一响应包括 requestId、状态、文本/候选字段、缺失字段、证据、Token 使用量和安全提示。协议层独立处理 OpenAI Responses/Chat Completions、Claude Messages、Gemini generateContent/streamGenerateContent。支持结构化输出的模型使用其原生能力；其余模型采用受约束 JSON 解析并严格校验，失败提示重试或手动填写。Schema 一致也不代表事实正确。

敏感数据先在本地处理：已知密码、API Key、私钥、验证器种子、Cookie、授权头和数据库密文禁止作为模型上下文。粘贴内容里的凭据优先本地拆分并移除；缺少可靠规则时要求用户删去。截图不能承诺自动识别并遮挡所有秘密，必须提供裁剪/遮挡与发送预览，不自动抓屏，不发送含登录二维码、私钥或 OTP 种子的截图。

日志、网页内容和截图中的指令视为不可信数据；模型建议不能改变允许字段或取得更多上下文。输出在原生层和业务保存层验证。命令只生成草稿，不自动执行；删除、修改云资源、证书部署和流水线重跑仍使用现有用户操作入口。

默认 HTTPS；本地回环 HTTP 网关允许用户明确选择，其他不安全地址需显式配置并提示。拒绝 URL 内凭据、未经允许的重定向密钥转发；Base URL 和协议路径采用明确规则，测试端口、路径前缀和代理兼容性。

默认不持久化提示词、输入截图和完整回答；调用日志只记录功能、模型、耗时、状态和 Token 数。用户主动保存的命令/备注等继续属于原业务数据。关闭 AI 不删除已有业务数据；删除服务配置停止后续调用并清除对应密钥。

桌面与手机原生壳复用 Rust 契约，但要分别验证插件、网络、权限与生命周期。浏览器预览首期明确显示 AI 原生能力不可用，不在前端保存 Key 或直接请求供应商；手动功能仍可用。以后需要浏览器 AI 时再设计拥有独立加密凭据与权限的本地 Node API，不模拟成功。

## 分阶段实施与验收

1. 调研与方案：核对当前执行层、已有解析器、迁移和业务入口，交付本方案与任务记录。首次方案阶段只完成此步骤。
2. AI 配置：设置界面、加密表与迁移、默认配置、能力状态和删除流程；验证普通偏好/日志不含密钥、重启恢复与加密迁移。
3. 统一调用：三协议适配、连接测试、取消、超时、结构化结果与统一辅助弹层；用本地可控服务验证成功、401、429、5xx、畸形 JSON、SSE 截断、能力不支持和过期响应。真实服务验收使用用户主动配置的服务。
4. 信息识别：先服务器、面板、DNS、资产/收藏的文本草稿，再截图；验证手动流程、结果缺失、批量重复项、现有表单不被覆盖、敏感字段移除和确认应用。
5. 诊断与命令：常用命令、选中终端输出、云效日志、操作/API 日志；验证上下文有界、证据与推测区分、命令不自动执行。
6. 配置与检索：证书/FRP/监控/OSS/云资源建议及自然语言筛选；验证建议不能绕开厂商校验，查询只允许既有筛选字段，不开放 SQL。
7. 完整验收：桌面/手机能力矩阵、浏览器明确降级、配置迁移、AI 关闭/不可达与注入防护；运行 build、Rust check/test、关键 UI/移动测试和平台契约等对应检查。逐步记录证据，全部完成前不归档任务。

首个可用里程碑为步骤 2～4：用户能配置任意一种服务，完成测试，在添加服务器和 DNS 表单中使用可选识别，并在失败时继续手动完成操作。后续功能不依赖聊天记录或全库上传。

## 官方协议依据

- OpenAI：[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)；结构化输出能力依赖模型与接口，仍需处理拒绝和不完整响应。
- Claude：[Messages API](https://platform.claude.com/docs/en/api/messages/create)；Messages 接口支持文本及图像内容。
- Gemini：[Structured outputs](https://ai.google.dev/gemini-api/docs/structured-output)；支持 JSON schema 的部分能力，需匹配所选模型。

第三方兼容网关可能只实现部分官方功能，必须测试，不承诺配置协议名即完整兼容。模型名称、价格与能力不硬编码为长期不变的事实。

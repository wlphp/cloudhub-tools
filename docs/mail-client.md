# 邮件管理客户端首版

入口：软件商店 → 邮件管理。桌面客户端使用原生 IMAP / SMTP；浏览器仅预览，手机暂未接入。

## 使用

1. 在邮箱服务商设置中开启 IMAP / SMTP，生成客户端授权码或应用专用密码。
2. 添加邮箱，选择服务商预设，核对服务器参数并保存。
3. 点击“检测连接”，分别检查 IMAP 与 SMTP；保存配置不代表连接成功。
4. 点击“收取邮件”，展示当前文件夹最近 50 封邮件。切换文件夹后重新收取。
5. 点击邮件阅读正文和附件，或点击“写邮件”“回复”发送邮件。

预设：QQ / Foxmail、网易 163 / 126 / yeah.net、腾讯企业邮箱、阿里企业邮箱、iCloud、自定义服务器。预设仅填参数，不代表所有套餐与账号已实测兼容。

## 范围

- 支持多个邮箱、本地配置增删改、收发连接检测、文件夹列表、纯文本阅读、读取后已读标记、主题和发件人本地筛选、写信、回复、附件收发。
- IMAP 使用隐式 TLS（通常 993）；SMTP 使用 TLS 或强制 STARTTLS，证书校验不可关闭。收发共用用户名与凭据。
- 阅读单封邮件上限 20 MiB；发信附件最多 10 个、合计 10 MiB；每个 IMAP 会话累计响应上限 32 MiB。
- 正文与附件不持久缓存；凭据由现有 AES-GCM 路径加密后保存在本地 SQLite，仅在用户点击授权码小眼睛时按需解密回显，隐藏或关闭后清除回显。不新增跨设备同步与迁移范围；当前配置不包含在可迁移备份中，迁移后需要重新添加。
- 邮件正文按纯文本显示，不执行 HTML、脚本或加载远程图片；仅含 HTML 的邮件提示使用网页版。
- 暂无 OAuth、POP3、离线缓存、自动后台同步、草稿持久化、删除/移动服务器邮件、回复全部、转发或联系人管理。
- SMTP 成功仅表示服务器接受。已发送副本由服务商处理，本版不自动 APPEND，部分服务商不会保存已发送副本。失败时保留当前写信内容，提示先核对记录再重试。
- 所有业务弹层使用 SharedDialog / ConfirmDialog；点击遮罩不关闭，写信有修改时关闭需确认。

## 实现

- React：src/features/mail/；调用：src/platform/clients/mail.ts。
- Rust：src-tauri/src/core/mail.rs、src-tauri/src/commands/mail.rs，仅主窗口调用。
- 数据库版本 59 创建 mail_accounts；协议依赖 imap、lettre、mailparse、native-tls，仅桌面编译。

## 验证边界

协议解析、MIME 生成与输入校验采用离线 Rust 测试；界面采用模拟原生命令的 Playwright 测试。没有接入真实用户邮箱，没有发送真实邮件；各服务商实际兼容性需由用户配置后验证。
